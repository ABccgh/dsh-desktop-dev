# 测试与验收

测试策略按金字塔分层：大量单元测试、适量集成测试、关键路径 E2E。

## 1. 层级与工具选型

| 层 | 目的 | 工具（按栈） |
| --- | --- | --- |
| 单元 | 纯逻辑、工具函数 | vitest/jest（Web）、xUnit/NUnit（.NET）、Qt Test（Qt） |
| 集成 | 模块协作、IPC、文件/DB | 同单元框架 + 测试替身；.NET 用 WebApplicationFactory 式宿主 |
| E2E | 真实用户路径 | Playwright（Electron/Tauri，`_electron.launch`）、WinAppDriver/FlaUI（WPF/WinForms）、Squish/Qt 自带（Qt） |

- 引入新依赖前先查 MEMORY.md 与现有测试脚本，优先复用既有设施。
- 构建脚本提供 `test` 命令并在 CI 强制执行。

## 2. 缺陷分级

- **P0 阻断**：崩溃、数据丢失、无法启动/安装 —— 立即修复，禁止发布。
- **P1 严重**：核心功能不可用、安全漏洞 —— 本版本修复或明确豁免。
- **P2 一般**：功能缺陷有绕行 —— 排期修复。
- **P3 建议**：体验/文案 —— 视情况处理。

每个缺陷记录：分级、复现步骤、期望 vs 实际、影响面、归属模块。

## 3. 手工测试清单（自动化未覆盖时逐项执行）

- [ ] 冷启动/二次启动；断网启动；低内存环境启动
- [ ] 100%/125%/150%/200% DPI 下的主界面与弹窗
- [ ] 浅色/深色/高对比度主题切换（运行中切换）
- [ ] 中文/日文输入法输入、候选窗、快捷键冲突
- [ ] 安装 → 使用 → 升级（保留数据）→ 卸载（询问数据清理）
- [ ] 崩溃恢复：异常退出后重启不丢数据、无残留锁文件
- [ ] 托盘：最小化到托盘、通知、退出入口
- [ ] 长任务进度、取消、超时、并发启动两个实例

## 4. 发布前验收门禁

- [ ] 单元/集成测试全绿，E2E 关键路径通过
- [ ] 无 P0/P1 未关闭缺陷；P2 缺陷有明确结论
- [ ] 手工清单中与本版本相关的项目完成
- [ ] 测试结论（含未覆盖项与风险）写入交付说明与 MEMORY.md

## 5. 回归策略

- 每个修复附回归用例（自动化或手工步骤）。
- 发布前对上次发布以来改动面做定向回归，而非全量重测。
