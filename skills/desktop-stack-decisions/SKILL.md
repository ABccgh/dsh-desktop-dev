# 桌面技术栈选型

先读项目 MEMORY.md 中已记录的架构决策，禁止与既有决策冲突而不说明理由。

## 决策维度（按权重排序）

1. **团队技能与现有资产**：已有代码、依赖与人员技能是最大权重。
2. **性能与资源**：内存占用、启动时间、CPU 敏感度。
3. **体积与分发**：安装包大小、依赖外置、商店合规。
4. **UI 复杂度**：数据密集/自绘 vs 表单/文档型界面。
5. **发布成本**：签名、更新通道、杀软误报风险。

## 决策树

- **需要复用现有 Web 前端（React/Vue 代码、UI 组件库）** → Electron 或 Tauri。
  - 安装包体积敏感、内存敏感、追求原生性能 → **Tauri**（Rust 后端）。
  - 需要完整 Node.js 生态、团队无 Rust、多窗口复杂场景 → **Electron**。
  - 已有大型 .NET 后端，仅少量 Web UI → **WPF/WinForms + WebView2** 混合。
- **纯 .NET 团队、数据密集/企业级界面（表格、表单、复杂布局）** → **WPF**（首选）/ **WinForms**（简单工具）。
- **C++/跨平台原生、自绘或高性能渲染** → **Qt**（Widgets 或 QML）。
- **只有少量脚本化小工具** → WinForms 或 Tauri，避免 Electron 的体积。

## 各栈速查

| 栈 | 优势 | 代价 |
| --- | --- | --- |
| Electron | 生态最大、Web 复用、迭代快 | 体积大（~100MB+）、内存高、杀软误报多 |
| Tauri | 体积小（<10MB）、内存低、Rust 安全 | 需 Rust、WebView2 依赖、生态较新 |
| WPF | .NET 生态、XAML 数据绑定、企业 UI 强 | 仅 Windows、较老、跨平台需 Avalonia |
| WinForms | 简单快速、成熟稳定 | UI 现代化成本高、布局能力弱 |
| Qt | 跨平台、性能好、工业级 | 授权成本（商业/动态链接 GPL）、C++ 复杂度 |
| WPF+WebView2 | .NET 主体 + Web UI 混合 | 两套栈、桥接复杂度 |

## 决策输出格式

每次选型决策产出 ADR（docs/adr/NNNN-<主题>.md）：

```markdown
# NNNN. <决策标题>
状态：已接受 / 已替代
背景：（要解决的问题）
决策：（选了什么，为什么）
备选：（评估过但放弃的方案与原因）
后果：（正面与负面代价、后续缓解）
```

选型完成后更新 MEMORY.md「架构决策」段，并通知相关技能（打包发布、UI 规范）以匹配新栈。
