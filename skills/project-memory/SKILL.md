# 项目记忆维护

记忆是团队连续性的根基：没有记录的工作等于没做。

## 1. 文件分工

| 文件 | 内容 | 特点 |
| --- | --- | --- |
| AGENTS.md | 稳定约定：编码规范、命令、目录结构、发布流程 | 低频变化，入库共享 |
| CLAUDE.md | 兼容性指令（与 AGENTS.md 同义时保持同步） | 可选 |
| MEMORY.md | 动态状态：架构决策、当前进度、已知问题、下一步 | 高频更新，随每次里程碑刷新 |

三个文件都会被自动加载（预算 256KB），更具体的优先。

## 2. MEMORY.md 结构（四段式）

```markdown
# 项目记忆

## 架构决策
- 2025-xx-xx <决策>：<一句话结论>，理由：<why>，见 docs/adr/NNNN

## 当前状态
- <进行中的工作与进度>、<最近完成的里程碑>

## 已知问题
- <未修复缺陷、技术债、环境坑>（带严重程度）

## 下一步
- <按优先级排列的待办>
```

## 3. 更新时机（完成后立即写，不拖延）

- 架构决策或技术选型确定后
- 新模块/接口/数据格式落地后
- 里程碑完成或方向调整后
- 故障排查出根因与修复后（沉淀"已知问题"或"坑"）
- 发布新版本后

原则：事实性、带日期、只记结论不抄全文；单次更新保持最小改动。

## 4. 新会话开场流程

1. 读取 AGENTS.md / MEMORY.md，识别当前状态与下一步。
2. 加载与本任务相关的技能（团队、选型、UI、打包、测试）。
3. 若上下文不足，用会话引用召回相关历史 session（@引用），追问用户前先查历史。
4. 基于记忆快速同步后，再动手或提问。

## 5. 跨会话召回

- 需要"上次做到哪了"时，优先召回历史会话而非重做勘察。
- 召回后把有效结论写回 MEMORY.md，让记忆自我增强。
- 压缩（/compact）后核对摘要是否保留了关键决策与数字，必要时回写 MEMORY.md。

## 6. 与团队的配合

- 子代理交付的结论由 Lead 提炼后写入 MEMORY.md，避免成员各自乱写。
- 文档与代码同步修改；发现文档过时立即更新或在"已知问题"登记。
